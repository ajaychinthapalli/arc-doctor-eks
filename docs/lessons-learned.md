# Lessons learned

Issues hit during the live build on `ac-ws-dev-use2`, in the order they came up.

| #   | Issue                                 | Symptom                                                                            | Cause                                                                       | Fix                                                                                                                                  |
| --- | ------------------------------------- | ---------------------------------------------------------------------------------- | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | No node autoscaler                    | Runners would stay Pending once the two t3.large nodes filled                      | Cluster had managed node groups only                                        | Installed Karpenter 1.14.1 with a tainted `linux-x64` NodePool for runners                                                           |
| 2   | IRSA not possible yet                 | —                                                                                  | Cluster OIDC issuer existed, but no IAM OIDC provider was registered        | `eksctl utils associate-iam-oidc-provider` (done in `karpenter/01-iam.sh`)                                                           |
| 3   | Tight capacity                        | ~1.4 vCPU free per t3.large, t3.small nodes near memory limits                     | Small dev cluster                                                           | Karpenter controller requests cut to 250m/512Mi; runners moved to Karpenter nodes; kagent Grafana MCP and bundled agents disabled    |
| 4   | Karpenter vs Kubernetes 1.36          | —                                                                                  | Kubernetes 1.36 needs Karpenter ≥ 1.13                                      | Pinned 1.14.1                                                                                                                        |
| 5   | Runner scale set stuck Pending        | Controller log: `POST /orgs/<user>/actions/runners/registration-token` → 404       | `githubConfigUrl` was a personal account, which ARC treats as an org        | Use `https://github.com/<user>/<repo>`; for many repos, use a GitHub org ([incident](../evidence/06-arc-runner-registration-404.md)) |
| 6   | kagent controller restarts            | `Error` / `CrashLoopBackOff` in the first 20 s                                     | Bundled PostgreSQL not ready yet                                            | None needed; stable after 3 restarts                                                                                                 |
| 7   | 10 bundled kagent agents              | Extra pods; `observability-agent` reconcile error for missing `kagent-grafana-mcp` | kagent 0.10.3 enables them by default; they point at an unused Ollama model | `--set <name>-agent.enabled=false` for each ([log](../evidence/09-kagent-disable-bundled-agents.log))                                |
| 8   | No Bedrock option in the kagent chart | —                                                                                  | Chart providers: OpenAI, Anthropic, Azure, Gemini, Ollama                   | Installed with `providers.default=ollama`; ARC Doctor uses its own Bedrock `ModelConfig`                                             |
| 9   | No Prometheus                         | —                                                                                  | Cluster uses CloudWatch                                                     | Removed the Prometheus tools from the agent                                                                                          |
| 10  | macOS blocked `kubectl -k`            | `open ..: operation not permitted`, `getcwd` errors                                | macOS privacy protection on `~/Downloads`                                   | Work from `~/arc-doctor`, or grant the terminal access to Downloads                                                                  |
| 11  | Agent card 404-like error             | `agent.json` returned a JSON-RPC `invalid request`                                 | kagent 0.10.3 serves A2A 0.3: the card is at `.well-known/agent-card.json`  | Updated docs; `message/send` format unchanged                                                                                        |
| 12  | Port-forward exited                   | `Exit 1`, empty `curl` replies                                                     | Port 8083 still held by an earlier port-forward                             | Used local port 18083                                                                                                                |
| 13  | Drill reported healthy                | Watcher said healthy right after the limit change                                  | No job was queued yet, and the stuck threshold is 5 min                     | Queue a job first; for tests, run the watcher locally with a 60 s threshold                                                          |
| 14  | Wrong mechanism in diagnosis          | Agent said a previous runner "consumed" the 1 vCPU                                 | Model assumed limits count pod requests                                     | Prompt now states limits count full node capacity; next drill explained it correctly                                                 |
| 15  | Slack formatting                      | `**bold**` and `##` shown raw                                                      | Slack uses its own markup (`*bold*`)                                        | Watcher converts bold and headings; tables still show as raw text                                                                    |
| 16  | Slack URL confusion                   | Pasted the Slack app URL                                                           | Webhooks are created in the Slack app's settings (`api.slack.com/apps`)     | Created an incoming webhook for `#arc-alerts`                                                                                        |
| 17  | Secrets in chat or history            | A webhook URL was pasted where others could read it                                | Anyone with the URL can post to the channel                                 | Remove that webhook in the Slack app and create a new one; always enter secrets with `read -s`                                       |

## Open improvements

- Convert Markdown tables to bullet lines in Slack posts.
- Tell the agent which file manages each NodePool, so its fix suggestion points
  to the right place.
- Add an `arc-ops` scale set so the on-demand GitHub workflow can run.
- Turn on spot instances: SQS interruption queue + `settings.interruptionQueue`.
- Replace the PAT with a GitHub App before it expires (90 days).
